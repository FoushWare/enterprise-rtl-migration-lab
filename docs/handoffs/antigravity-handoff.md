## Scope and architecture

RTL Analyzer is the scanner, report dashboard, review workflow, candidate preview, validation, Apply, rollback, and history system in this repository. It is distinct from the sample migration applications under `apps/` and from the disposable Field Notes fixture created by the browser harness. The relevant implementation is under `tools/rtl-scanner/src/`; scanner unit tests are under `tools/rtl-scanner/tests/`; browser scenarios and disposable-target runners are under `tests/e2e/`; product and verification records are under `docs/rtl-analyzer-v3/` and `docs/project-memory/`.

The dashboard is generated by `dashboard-html.ts` and `dashboard-client.ts`. Review lifecycle and the sticky toolbar/menu are in `dashboard-review-workflow.ts`; the read-only Review details modal is in `dashboard-review-details.ts`; real Before/After iframe state and fullscreen are in `dashboard-embedded-preview.ts` and `dashboard-contextual-preview.ts`. Candidate ownership, validation freshness, Apply, backup, rollback, and rescan remain in the existing workflow/companion modules. `tests/e2e/serve-independent-onboarding.mjs` creates a new disposable target outside the repository and never represents a production application.

The root package is `atlas-invoice`, while `tools/rtl-scanner` is a TypeScript tool compiled into ignored `dist/tools/rtl-scanner`. The scanner CLI and dashboard generation are verified locally through the `rtl:scan:*` scripts and the browser harness. The publishable npm-package surface, registry metadata, package provenance, and a real consumer install are not verified by this checkpoint; do not infer npm publication readiness from the dashboard tests.

## Latest implementation

The workspace now has only `Project Explorer | Findings | Review pane`. The duplicated workspace Navigation column, its rail, collapse handler, width, and positional selectors are removed. Global-header navigation remains unchanged. Explorer and Findings collapse independently using bounded named columns; both collapsed at 1600px leave a 1508px review pane. The review pane has the finding title/path, sticky session toolbar, bounded source, compact Details, exact Before/After code, real live previews, and compact Decision.

The toolbar shows the review mode, accepted count, validation status, Review details, one next action, and an accessible overflow menu. Zero accepted changes use the concise disabled `Validate changes` label. Preview state is represented by separate badges, with real route/direction/viewport/target controls, automatic preparation, recovery, diagnostics, and preserved iframe/fullscreen state. Review details uses icon tabs, segmented current/history context, compact summary cards, connected timestamped activity, validation scopes, exact changes, Technical identities, and Copy controls. Semantic-review reasoning remains collapsed until requested. Validation and Apply policy was not changed: only accepted, fresh, verified candidate evidence can reach Apply; historical validation never validates a new current review; rollback restores source and starts a fresh Pending / Not run review.

## Fresh-clone setup and reproduction

Use Node/npm versions accepted by the repository's existing lockfile and CI. From the repository root:

```sh
npm ci
npm run rtl:scan:typecheck
npm run rtl:scan:build
npm run rtl:scan:test
npm run typecheck
npm run build
```

To generate a standalone dashboard from a repository or disposable target, build the scanner first and use an output directory that already exists:

```sh
mkdir -p /tmp/rtl-analyzer-dashboard
node dist/tools/rtl-scanner/cli.js --root /path/to/target --format dashboard --embed-source-snippets --output-dir /tmp/rtl-analyzer-dashboard
python3 -m http.server 4320 --bind 127.0.0.1 --directory /tmp/rtl-analyzer-dashboard
```

For the complete disposable browser harness, use the repository runners. They install dependencies only inside newly generated temporary fixtures when `RTL_ONBOARDING_INSTALL=1`; they do not write the sample target in this repository:

```sh
npm run rtl:scan:build
RTL_WORKSPACE_OUTPUT_PREFIX=test-results/antigravity-workspace node tests/e2e/run-review-workspace.mjs
RTL_REVIEW_SPECS=tests/e2e/review-workflows-complete.spec.ts node tests/e2e/run-review-workflows.mjs
```

The independent runner prints `ONBOARDING_ENVIRONMENT /absolute/path/environment.json` and the dashboard URL. Read that JSON to discover the project, state, dashboard, owned supervisor, and child PIDs. The workflow runner prints its evidence directory. Run scenarios on separate fresh fixtures rather than reusing a completed workflow. Apply/rollback tests must use only these disposable targets.

If a runner is interrupted, inspect the JSON's `supervisorPid`, `children`, project root, and command line before cleanup. Stop only the owned supervisor with `kill -TERM <verified-supervisor-pid>`; it will stop its registered children. Do not kill by port alone. Temporary fixture directories and ignored evidence may be removed later only after confirming they are disposable and no longer needed. Never use credentials, authentication state, `.env` files, `node_modules`, caches, or generated `test-results` as handoff prerequisites.

## Workflow boundaries

Decision state belongs to the selected finding. Notes and selected action persist with that finding. Candidate preparation is automatic for eligible findings and is protected against stale responses, duplicate requests, mismatched finding/source identity, and unrelated runtime origins. Validation is fresh, candidate-scoped, and reports project checks separately from scanner/runtime evidence; missing commands are Not configured, not evidence that tests do not exist. Apply is explicit and accepted-only. Source backups, hash checks, ownership checks, confirmation, and rollback protections remain active. Rollback restores source and starts a new review; previous decisions, validation, receipts, and backups remain read-only historical evidence and are never inherited by the fresh review.
