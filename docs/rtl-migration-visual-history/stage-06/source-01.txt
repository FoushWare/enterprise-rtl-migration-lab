0011  ## Implementation and validation rules
0012
0013  An explicit validator checks external JSON before returning a Policy. It reuses the existing TypeScript JSON AST for duplicate JSON members, JSON-pointer record locations and exact UTF-16 offsets. No dependencies were added. Validation rejects unknown fields, unsupported schema versions/rule IDs, missing required fields, invalid enums, wrong primitive/container shapes, incompatible mechanism ownership, duplicate records and contradictory owner/exception declarations. It does not coerce values.
0014
0015  Policy schema version remains 1. Required top-level fields remain schemaVersion, generatedStyleOwner, ownership, approvals, exceptions, issueBindings, dynamicExceptions and roles; ownerOverrides remains optional. Paths must be normalized repository-relative POSIX paths without parent traversal, absolute/drive paths or backslashes. Unicode paths remain supported. Pins require lowercase 64-character SHA-256 digests. Resource bounds are one million policy characters, ten thousand array entries and 4,096 characters per validated string. Malformed JSON and existing symlink config files fail explicitly; absent config retains the previous empty-policy behavior.
0016
0017  Supported owners and mechanism mappings are checked. Generated ownership remains separate from authored CSS/inline/Emotion ownership. Unknown ownership does not establish automation eligibility. Overrides must resolve to a compatible extracted context. Conflicting approvals and exceptions on the same declaration block. Semantic approvals require an exact unique declaration, whole-file source pin, matching owner and supported logical equivalent; applicability also reuses the unchanged conservative detector's admission safeguards. This does not establish semantic intent independently or grant transformation authorization. The actual approval list remains empty.
0018
0019  Dynamic exceptions remain restricted to the reviewed background-property catalog. Their source digest, expression digest and applicable extracted dynamic diagnostic must match. They cannot become broad directional suppression. The two English HTML-root exceptions match their existing exact finding anchors and declaration hashes.

0021  ## Stale policy, coverage and exits
0022
0023  Auditing uses the unsuppressed source catalog. Records cannot validate themselves against an already suppressed result. Diagnostics point to the existing repository-relative policy filename and the record's JSON source span, including its pointer in the message.
0024
0025  | Record or condition | Diagnostic treatment |
0026  | --- | --- |
0027  | Stale semantic approval | BLOCKING, POLICY_STALE_APPROVAL |
0028  | Stale ownership override | BLOCKING, POLICY_STALE_OVERRIDE |
0029  | Stale intentional/directional exception | BLOCKING, POLICY_STALE_EXCEPTION |
0030  | Changed/unmatched dynamic-background pin | BLOCKING, POLICY_STALE_DYNAMIC_EXCEPTION |
0031  | Stale reference binding or brand association | WARNING, POLICY_STALE_INFORMATIONAL |
0032  | Stale metadata-only INFORMATIONAL document exception | WARNING, POLICY_STALE_INFORMATIONAL |
0033  | INFORMATIONAL exception on a directional rule | Remains a directional suppression; stale record blocks |
0034  | Unsupported source coverage for effect-bearing record | BLOCKING, POLICY_UNSUPPORTED; source coverage diagnostic also retained |
0035  | Incompatible/contradictory owner or approval | BLOCKING, POLICY_CONFLICT |
0036  | Invalid generated finding identity | BLOCKING, POLICY_FINDING_ID_INVALID |
0037  | Invalid schema/input or duplicate record | Rejected before scanning; source-located POLICY_INVALID/POLICY_DUPLICATE or specific invalid-path/JSON code |
0038  | Unsupported policy version/rule | Rejected before scanning, POLICY_UNSUPPORTED |
0039
0040  A blocking policy audit disables effect-bearing approvals, exceptions, dynamic exceptions and ownership overrides in the partial report; source evidence and unsuppressed risks remain available. Metadata associations do not authorize transformations. No records are refreshed or removed automatically.
0041
0042  CLI exit behavior preserves precedence: invalid policy errors emit stderr and exit 2 without a successful JSON report; blocking audit/source coverage emits an incomplete partial report and exits 2. Warning-only stale metadata allows complete=true and default exit 0. An explicit --fail-on-findings returns 1 for actionable findings only when analysis is complete; exit 2 always wins. Complete still means no blocking coverage/analysis uncertainty, not zero risks or zero warnings. No CI gate was enabled.
