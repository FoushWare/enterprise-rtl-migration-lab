### Rules and ownership policy

Rules cover physical horizontal CSS/MUI aliases and inline styles; border/spacing/shorthand/corner risks; absolute/fixed edges and matching shell gutters; mobile transforms/order; document/theme/cache correlation; directional icon imports and rendered literal arrows; fixed SVG/separate HTML flex-label flow; unisolated content sinks; reviewed brand-role direction islands; and generated form/table/pagination policies.

`rtl-scanner.config.json` is data-only. It distinguishes custom CSS/inline ownership, custom Emotion/sx/theme styles pending direction-pipeline review, generated MUI styles, reviewed initial-English exceptions, and unknown/conflicting owners. Overrides with conflicting owners produce manual-review findings. No runtime providers, plugins, app styling or translations are changed.

**Semantic approvals are empty.** Physical properties never qualify solely by name. Candidate admission requires an exact source fingerprint, reviewed declaration/value/intent/owner, bounded correct logical equivalent, supported value and no relevant uncertainty/conflict. MUI sx stays manual because alias/unit processing for logical equivalents has not been verified; theme direction alone does not fix generated physical styles. The only actual intentional exceptions are the approved initial English document roots. Latin identifiers, chart geometry and the currently unisolated brand are not automatically exempted.

### Scope limits and decisions requiring review

This remains syntax/import-binding analysis, not a complete TypeScript/import/provider/cascade graph. Shared application reachability is not automatically attributed: app-file findings use source-path attribution; an empty shared application list means unresolved reachability, not no affected apps. The matrix uses the existing reviewed application/component evidence. Missing cache is a scoped absence inference; outside/re-exported configuration can invalidate it.

Shorthands/corners/custom variables and transforms receive conservative manual handling; there is no transformation engine or complete CSS grammar/cascade solver. Escaped/interpolated templates remain diagnosed rather than evaluated. Bidi candidates cover bounded name/address/email/ID expressions and imported money sinks, not complete arbitrary-string flow or native date/caret semantics. SVG/flex-label correlation cannot prove chronology; glyph overlap cannot be statically measured. Intentional LTR chart/brand target conventions remain semantic decisions, not blanket suppressions.

Foundation adapter correction: PostCSS end offsets are already exclusive. Stage 3 removed the erroneous extra character and added an exact-boundary regression test. Responsive sx branch extraction and semantic AST ID normalization were strengthened for the detection rules. These changes affect scanner evidence only, not application code.

Review before further work: ownership/exception/source-pinned background policy; the seeded reference bindings and brand role; the conservative risk priorities/noisy bidi/column-policy entries; and coverage limits requiring future graph/cache/escaped-template work. No automatic source approval, codemod, RTL plugin, remediation, dashboard or CI gate is authorized by these findings. Stage 4 remains unstarted.

**Closure:** the [closure audit](phase-3-stage-3-closure.md) records the documentation conditions, final verification and exact intended files. Conditional approval authorizes a Stage 3 commit only after those checks pass. Nothing is pushed; Stage 4 and all transformations remain unauthorized.

### Closure qualifications

Policy validation is partial, not a complete runtime schema. TypeScript interfaces do not validate JSON at runtime. Only malformed configurations currently detected by the loader are guaranteed to exit 2; owner/role/override shapes, field types, normalized paths and digest formats are not comprehensively checked. Unmatched or stale policy entries have no explicit stale-policy diagnostic. Whole-file SHA-256 pins deliberately invalidate dynamic exceptions even after unrelated source edits. Exact-match exception handling is not a general-purpose suppression mechanism and does not remove the nine coverage diagnostics. Strict schema validation, stale-entry diagnostics and complete ownership/override validation are prerequisites for automated transformations or CI enforcement; none was implemented during closure.

Shared report entries retain `applications: []`: reachability unresolved, not zero consumers. Reviewer-observed associations in the [final adjudication consumer table](phase-3-stage-3-final-adjudication.md#shared-attribution-evidence-not-inferred-universal-reachability) distinguish cross-application Provider/FormField/DataTable/shell/status/formatter consumers from invoicing-only Modal and dashboard chart/icon structures. These associations do not fabricate a scanner-computed import/provider/selector graph.

The nine-case matrix is reference calibration, not a precision benchmark. RTL-04/06/07 share the same theme finding and must not be counted as three independent root causes. Standalone total and confirmation name links in RTL-08 remain additional unconfirmed candidates; fixed en-US formatting was intentionally retained. Phase 2A observed severity remains separate from scanner source priorities. The three proposed `.status-dot`, `.chart-legend i` and `.kpi-note b` spacing declarations remain unchanged MANUAL_REVIEW candidates, with no semantic approvals or AUTO_CANDIDATE promotion.
